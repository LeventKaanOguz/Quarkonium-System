# Archive of the fit results (v1.1.0)

`results-v1.1.0.tar.gz` holds the logged output of every fit of the paper: one JSON file per configuration
(parameters, covariances, masses, widths, convergence checks) and its printed table, for each sweep of
`analysis/sweep.py` (`main`, `floor`, `floor0`, `floor2`, `joint`, `joint2`, `widths`, `cv`, `stats`, `nested`,
`lm`, `minuit`, `bopt`, `bgrid`, `shape`, `rel`).

    (cd results-archive && sha256sum -c SHA256SUMS)
    tar xzf results-archive/results-v1.1.0.tar.gz   # creates results/ in the repository root
    python3 analysis/analyze.py            # regenerates tables and figures from the JSON (needs ROOT)

The fits are regenerated by `python3 analysis/sweep.py all` (several hours on a few cores); the sweeps are seeded
(`seed` in every JSON). After the sign fix of v1.1.0 the widths of every configuration with S–D mixing were
recomputed in the `main`, `floor2`, `joint`, `joint2`, `widths` and `stats` sweeps, which are the ones the analysis
reads (`stats_mcmc/` holds the chains rerun for the `stats` sweep). The sweeps that the analysis does not read for
widths (`cv`, `nested`, `bgrid`, `shape`, `rel`, `lm`, `minuit`, `bopt`, `floor`, `floor0`) store widths from before
it (see CHANGELOG).

## Added in v1.2.0

`results-v1.2.0.tar.gz` (`results-v1.2.0/`) holds the runs that are not part of the v1.1.0 sweeps: `rep` (the four
representatives again, with the B_c interpolation systematic), `oneloop` (the one-loop short-distance potential of
Models A and B at three reference scales), `cx` (fits with a mixed real + complex-range basis), `screen` (the screening
mass fitted, shared and profiled) and `studies` (`qgem_study`: exact GI sandwiches, the contact term, complex-range
convergence). `python3 analysis/sweep.py rep oneloop cx screen studies` regenerates them from the v1.1.0 minima (they
are the seeds), `python3 analysis/summarize_v12.py` writes `v1.2-summary.md`. Every run has a `.log` with its command
line (`qgem --log`).
